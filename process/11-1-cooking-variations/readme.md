# 11-1: 調理状態バリエーション検出

MEXTデータの各食品について、同じ基本食品名（baseName）を持つ他の食品の調理状態バリエーションを検出し、相互参照情報を追加します。

## 入力

- `../10-1-recipe-ingredient-mark/result/final-nutrition-with-recipe-flag.csv` – MEXT食品データ（構造化食品名を含む）

## 調理方法の定義（Cooking Labels）

栄養素の「逃げ道」と「水分変化」に基づいた6つの分類 + 初期状態です。

### 調理工程ラベル

| ラベル | 英語名 | 定義・栄養素の状態変化 |
| :--- | :--- | :--- |
| **調理なし** | **RAW** | 非加熱の状態。食材本来の水分・栄養価を100%（基準）とする。 |
| **茹でる（捨てる）** | **DRAINED** | 水中で加熱し、ゆで汁を分離する工程。水溶性栄養素（カリウム・ビタミンB/C）が最大流出する。 |
| **茹でる（使う）** | **SOUPED** | 水中で加熱し、汁ごと摂取する工程。栄養は汁に溶け出すが回収される。加水により栄養密度は下がる。 |
| **蒸す（レンジ）** | **STEAMED** | 蒸気または電磁波で加熱する工程。水への溶出がなく、熱分解のみ。RAWに最も近い組成を維持。 |
| **焼く・炒める** | **SEARED** | 乾熱または少量の油で加熱する工程。水分が蒸発し栄養が濃縮される。脂溶性ビタミンも保持。 |
| **揚げる（素揚げ）** | **FRIED** | 油中で高温加熱し、油を切る工程。水分が抜け、代わりに油が浸透する。脂溶性が油側に逃げる。 |

### 食材の初期状態（FOOD_STATE）

調理工程（プロセス）ではなく、レシピに使用する時点での食材の状態。計算の「起点」として使用。

- 乾物、缶詰、冷凍、漬物、干物など、すでに加工・保存処理がなされた状態。

## 処理内容

1. **グループ化**: 各食品を`getGroupKey`関数を使用して、調理状態以外の属性（baseName、部位、品種、生産方法など）でグループ化
2. **バリエーション検出**: 同じグループ内で異なる調理状態を持つ食品を検出
   - バッチ処理はオーバーラップ方式（例：バッチ30件で20件進む）で境界問題を解決
3. **相互参照生成**: 各食品に他の調理状態への参照情報を追加
   - 例: 「豚肉 生」（food_number: 001）→ `{"DRAINED": ["002"], "SEARED": ["003"]}`
   - 例: 「豚肉 ゆで」（food_number: 002）→ `{"RAW": ["001"], "SEARED": ["003"]}`
   - 例: 「豚肉 焼き」（food_number: 003）→ `{"RAW": ["001"], "DRAINED": ["002"]}`

## 出力

- `result/final-nutrition-with-cooking-variations.csv` – 元CSVに以下の列を追加した最終成果物
  - `cooking_label`: この食品の調理ラベル（RAW, DRAINED, SOUPED, STEAMED, SEARED, FRIED, FOOD_STATE）
  - `cooking_variations`: 他の調理状態への参照情報（JSON形式）
- `result/cooking-labels.json` – 調理ラベルの定義とマッピング
- `result/variation-stats.json` – 検出されたバリエーションの統計情報

## 実行

```bash
pnpm run process:11-1
```
